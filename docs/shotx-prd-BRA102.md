# ShotX BRA-102 变更单（录屏体验：权限置顶、隐私默认、摄像头画中画）

版本：v1.0
状态：已确认需求，进入设计与开发
日期：2026-08-16
对应需求：BRA-102（父工单）
优先级：本变更单优先于既有规范中的冲突表述（冲突点名见 §7）

## 1. 用户问题

用户反馈录屏首次体验的三点问题：

1. **首次打开软件的权限申请**：第一次打开软件应先发起权限申请，且权限申请页面必须保持在最高层、不影响用户点击。现状：系统权限申请在用户绘制矩形后出现在截图/录屏蒙层的下一层，根本没法点击，与「开始录屏」冲突、阻断，第一次操作非常沮丧，用户怀疑会造成重大用户流失。
2. **第一次录屏的隐私保护**：第一次录屏时摄像头和麦克风应默认禁用。
3. **摄像头画中画**：开启摄像头后立即调用系统摄像头，摄像头画面以圆角正方形出现在截图/录屏矩形的左下角（带一点 margin）。提供大、小两档尺寸选择，并增加摄像头设置开关（若系统支持）：模糊背景、美颜、镜像。用户表示已更新设计文件，要求按设计样式严格执行 UI。

## 2. 范围与用户流程

1. 首次启动：进入后即发起所需权限申请（屏幕录制），权限弹窗保持最高层级、可点击，不与后续截图/录屏蒙层冲突、不阻断操作。
2. 首次录屏：摄像头、麦克风默认关闭；不自动发起其权限请求。
3. 区域录屏设置态：开启摄像头开关后立即启动系统摄像头，在选区左下角显示圆角正方形画中画（带 margin）；提供大/小两档尺寸与摄像头设置开关（模糊背景、美颜、镜像，系统支持时生效）。
4. 录制中：画中画按所选尺寸与设置实时呈现，并与成片一致；画中画与选区边框/遮罩层级关系正确，仅叠加在录制内容范围内。

## 3. 功能要求与验收标准

| ID | 要求 | 验收标准 |
| --- | --- | --- |
| BRA102-01 | 首次启动发起权限申请且弹窗置顶可点 | 首次打开即出现权限申请；弹窗位于所有 ShotX 蒙层之上，可正常点击授权/拒绝；与「开始录屏」不冲突、不阻断 |
| BRA102-02 | 首次录屏摄像头/麦克风默认禁用 | 全新安装首次录屏时摄像头与麦克风均为关闭，且不自动弹出其权限请求 |
| BRA102-03 | 摄像头画中画：开启即启动摄像头 | 开启摄像头开关后立即调用系统摄像头并出现预览，无需等录制开始 |
| BRA102-04 | 画中画位置与形态 | 圆角正方形，位于录制选区左下角，带 margin |
| BRA102-05 | 两档尺寸 | 提供大/小两种尺寸选择，选择后录制中实时生效 |
| BRA102-06 | 摄像头设置开关 | 模糊背景、美颜、镜像开关（系统支持时显示并生效；不支持时隐藏或明确禁用并说明） |
| BRA102-07 | 画中画与录制一致性 | 设置态预览与成片中的画中画位置、尺寸、形态一致；画中画不超出录制选区 |

## 4. 关键状态

| 状态 | 用户可见反馈 | 可执行动作 |
| --- | --- | --- |
| 首次启动权限 | 置顶权限弹窗，说明用途 | 授权、拒绝、打开系统设置 |
| 录屏设置（摄像头关） | 摄像头开关默认关闭 | 保持关闭或开启 |
| 录屏设置（摄像头开） | 选区左下角出现圆角正方形摄像头画面；可选大/小尺寸与模糊/美颜/镜像 | 调整尺寸/设置、关闭摄像头、开始录制 |
| 录制中 | 画中画实时呈现，与成片一致 | 停止录制；画中画与遮罩均不拦截选区操作 |

## 5. 非功能与非目标

- 仅使用现有 AppKit/AVFoundation/ScreenCaptureKit 与系统 API；不新增第三方依赖或网络服务。
- 摄像头画中画仅用于录屏场景；截图不涉及。
- 模糊背景/美颜/镜像以系统能力为限（如 `AVCaptureDevice` 相关能力），不支持时不得以假实现冒充。
- 非目标：不自研美颜算法、不改变录屏选区/遮罩/成片尺寸口径、不引入账号或云端。

## 6. 追踪与验证

`BRA102-01…07` → UX 交互标注 → 客户端实现 → 单元/回归测试 + 独立 QA 手测清单。依赖真实摄像头与系统权限弹窗的用例按仓库既有交付模型（`docs/RELEASE-AND-TEST-POLICY.md`）改为包体交付 + 用户手动验证；团队侧仅执行可后台运行的自动化验证。

## 7. 与既有规范的关系（冲突点名）

- `REC-03`（不提供摄像头录制）被本变更单 `BRA102-03/04/05/06/07` 取代：摄像头以画中画形式进入 MVP 范围。
- `FR-BRA71-07`「Figma 的摄像头图层不纳入实现」表述随之失效。
- 权限申请时机由「捕获触发时」调整为「首次启动即发起并置顶」，覆盖 `BASE-03` 的部分交互表述；`BASE-04`（麦克风按需申请）保持不变。
