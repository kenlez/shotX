## 1. 首次启动权限流程（BRA102-01/02）

### 1.1 目标问题

现状（代码核实）：权限请求只在用户触发捕获命令（`AppModel.begin` → `requestScreenPermission`）或绘制选区后才触发；捕获蒙层窗口使用 `.screenSaver` 级（`CaptureCoordinator.swift:301`、`RecordingCoordinator.swift:801`），系统屏幕录制权限弹窗（TCC）出现在蒙层之下，无法点击，与「开始录屏」冲突、阻断。

### 1.2 权限请求时机（BRA102-01）

| 时机 | 行为 |
| --- | --- |
| 首次启动（全新安装后第一次运行） | 进入 W-ONB（`shotx-ux-ui-spec.md` §4.1，480×420 普通窗口层级）后**立即**通过「开始设置」发起屏幕录制权限请求（`CGRequestScreenCaptureAccess()`）；此时无任何捕获蒙层存在，系统弹窗自然置顶、可点击 |
| 非首次启动 | 不自动弹系统权限请求；权限状态在 `W-SET/权限` 显示，捕获命令可随时触发权限拦截说明 |
| 捕获命令触发且权限未授予 | 权限检查前置：未授权**不创建选区蒙层**，先显示权限拦截说明（复用 `shotx-ux-ui-spec.md` §4.2 精确文案），按钮「打开系统设置」「取消」 |

**行为变化**：权限申请时机由「捕获触发时」调整为「首次启动即发起并置顶」，覆盖 `BASE-03` 部分交互表述（PRD §7）。

### 1.3 弹窗层级保证（BRA102-01，验收关键）

**规则（开发不可自行猜测）**：发起任何系统权限请求（屏幕录制 / 摄像头 / 麦克风）时，ShotX 必须**不存在任何 `.screenSaver` 级全屏蒙层或遮挡窗口**。

具体约束：

1. 首次启动：W-ONB 使用普通窗口层级（非 `.screenSaver`），请求在 W-ONB 打开期间发起，蒙层未创建。
2. 从捕获命令触发：先执行权限检查，未授权 → 进入权限拦截说明（§1.2），**绝不**先建选区蒙层再弹系统权限请求（这是现状缺陷根因）。
3. 从 `O-RSET` 内开启麦克风/摄像头触发权限请求时：`O-RSET` 面板为 `screenSaver+1` 级，系统权限弹窗可能被面板遮挡。**约束**：请求期间面板不覆盖屏幕中央；若系统权限弹窗与面板同屏冲突，实现须在请求前将面板临时降级为普通层级或请求结束后再聚焦面板（两方案任选，须保证弹窗可点）。
4. 与「开始录屏」的关系：权限弹窗只阻塞自身交互；授权/拒绝后均不阻断后续操作。拒绝屏幕权限时捕获命令仍可点击，点击进入拦截说明（不是无反馈禁用，`shotx-ux-ui-spec.md` §5 状态变体）。

### 1.4 首次录屏摄像头/麦克风默认禁用（BRA102-02）

代码核实：`AppSettings` 中 `microphone = false`、`camera` 默认 `false`（`AppModel.swift:81-83`），当前实现已满足默认关闭。

| 项 | 规则 |
| --- | --- |
| 全新安装首次进入 `O-RSET` | 摄像头开关**默认关闭**、麦克风开关**默认关闭**；不自动发起摄像头/麦克风权限请求 |
| `W-SET/录屏` 分区 | 「摄像头画面」「麦克风」开关默认关闭（与 `O-RSET` 同一数据源 `AppSettings`） |
| 权限请求触发 | 仅当用户**主动开启**对应开关时才请求对应权限（沿用 `FR-BASE-04` 按需申请口径，仅扩展到摄像头） |
| 拒绝后 | 对应开关自动关闭，显示「{麦克风|摄像头}不可用。你仍可继续无{麦克风|摄像头}录制。」+「打开系统设置」（复用现有文案模板，见 §4） |

## 2. 摄像头画中画（BRA102-03/04/05/07）

### 2.1 开启即启动（BRA102-03，行为变化）

现状（代码核实）：摄像头会话与预览窗口只在**录制开始后**创建（`RecordingCoordinator.swift:231-234`）。

| 状态 | 规则 |
| --- | --- |
| `O-RSET` 设置态开启摄像头 | **立即**请求摄像头权限（若未授权）→ 启动 `AVCaptureSession` → 选区左下角显示画中画预览，**无需等录制开始** |
| 录制中 | 画中画按设置态同样的位置/尺寸/设置实时呈现，与成片一致 |
| 摄像头权限未授予 | 开关自动关闭 + 提示（§4），不出现画中画 |
| 无摄像头设备 | 开关自动关闭 + 提示「未找到摄像头」（§4），不出现画中画 |

### 2.2 位置与形态（BRA102-04）

**与现状的差异（开发必改）**：现状 `CameraOverlayLayout.rect`（`RecordingCoordinator.swift:72-81`）把画中画放在选区**右下角**且为 **4:3 竖矩形**；PRD 要求**圆角正方形**、选区**左下角** + margin。实现必须改为：

| 项 | 规格（待确认） | 说明 |
| --- | --- | --- |
| 形态 | 圆角正方形，边长 = 边长 pt，圆角半径 **12 pt** | 与 `record-menu` 面板圆角、现 preview `cornerRadius = 12` 一致；待设计文件确认 |
| 位置 | 选区**左下角**；画中画左边缘距选区左边缘 **margin = 12 pt**，下边缘距选区下边缘 **margin = 12 pt** | 待设计文件确认（可能为动态 margin） |
| 坐标口径 | 预览窗口用选区 point 坐标，成片合成用输出像素坐标（pt × backingScaleFactor）；**两处必须调用同一布局函数**，仅坐标系不同，保证一致 | 复用现有 `CameraOverlayLayout` 但改为正方形+左下角 |
| 画面填充 | `resizeAspectFill`（等比填充、裁切超出的边），圆角裁切 | 与现状 `videoGravity = .resizeAspectFill` 一致 |
| 方向 | 镜像开关（§3）控制水平翻转，预览与成片同步应用 | 见 BRA102-07 |

### 2.3 两档尺寸（BRA102-05）

| 档 | 边长（pt） | @2x 成片像素 | 说明 |
| --- | --- | --- | --- |
| 小 | 96 × 96 | 192 × 192 | 待设计文件确认 |
| **大** | **192 × 192** | **384 × 384** | 待设计文件确认；按设计图仅提供大/小两档 |

**夹紧规则（开发不可自行猜测）**：

1. `available = min(选区宽, 选区高) − 2 × margin`；
2. `side = min(选中档边长, available)`；若 `side < 64 pt`（含 margin 后无法容纳最小档），**隐藏画中画**并在设置面板显示提示「选区过小，无法显示摄像头画面」；
3. 画中画**任何情况下不超出录制选区**（BRA102-07）。

**切换生效**：尺寸在设置态选择后**立即实时生效**（预览即时变化）。录制中不提供改尺寸入口（沿用 `shotx-ux-ui-spec.md` §3.1「录制中仅停止录制/设置…/退出可用」约束）；「选择后录制中实时生效」按「所选值在录制开始时被锁定并全程生效」实现，录制中不可改（待确认是否需要在录制中临时调整）。

### 2.4 画中画与选区/蒙层的层级关系（BRA102-03/07）

| 项 | 规则 |
| --- | --- |
| 窗口层级 | 画中画预览窗口高于选区遮罩（`screenSaver`），低于/不遮挡 `O-RSET` 面板交互区；沿用现状 `screenSaver + 2` |
| 鼠标 | 画中画窗口 `ignoresMouseEvents = true`，不拦截选区拖动、把手操作、面板点击（沿用现状 `RecordingCoordinator.swift:580`） |
| 遮罩 | 画中画仅叠加在录制内容范围内（选区孔洞内）；选区外四块遮罩 100% 纯黑，画中画不得出现在遮罩之上 |
| 不入成片 | 预览画中画窗口是 ShotX 自身窗口，属捕获排除层（沿用「所有 ShotX 窗口加入 ScreenCaptureKit 排除列表」）；成片中的画中画由录制管线合成，不入屏显窗口画面 |
| 一致性 | 设置态预览与成片中的画中画位置、尺寸、形态必须逐像素一致（BRA102-07）；预览窗口坐标 = 选区左上角 + 布局 rect（pt），成片 rect = 同一布局函数（px），仅缩放因子不同 |

### 2.5 设置态→录制中的生命周期

| 事件 | 行为 |
| --- | --- |
| 设置态开启摄像头 | 创建会话 + 预览窗口显示（选区左下角） |
| 点击「开始录制」 | 锁定当前选区与画中画尺寸/设置快照；设置态预览窗口沿用（不重建）；录制管线用同一布局函数合成 |
| 倒计时 `Esc` 返回 | 返回 `O-RSET`，画中画预览保持显示，选区/尺寸可继续调整 |
| 停止录制 | 关闭预览窗口，销毁会话 |
| 摄像头设备断开（录制中） | 画中画预览关闭、成片该轨从断开点消失（后续帧不含画中画）；显示横幅「摄像头已断开，其他来源仍在录制。」（复用麦克风断开文案模板，`shotx-ux-ui-spec.md` §10.4） |

## 4. 摄像头状态矩阵（空态/加载态/错误态）

| 状态 ID | 触发 | 用户可见反馈 | 可执行动作 |
| --- | --- | --- | --- |
| `CAM-off` | 摄像头开关关闭 | 无画中画；图标 `record-camera-off.svg` | 开启摄像头、调整选区、开始录制 |
| `CAM-starting` | 开启开关，会话/首帧就绪中 | 画中画区域内显示 loading（小型 spinner +「正在启动摄像头…」），首帧到达后替换 | 等待；可关闭摄像头 |
| `CAM-on` | 会话运行 | 画中画实时预览；图标 `record-camera-on.svg` | 调尺寸/设置、关闭摄像头、开始录制 |
| `CAM-no-device` | 无摄像头设备时开启 | 开关自动关闭；横幅「未找到摄像头」 | 关闭摄像头、继续无摄像头录制 |
| `CAM-no-permission` | 权限被拒绝/受限时开启 | 开关自动关闭；横幅「摄像头不可用。你仍可继续无摄像头录制。」+「打开系统设置」 | 打开系统设置、继续无摄像头录制 |
| `CAM-lost` | 录制中设备断开 | 画中画消失；横幅「摄像头已断开，其他来源仍在录制。」 | 继续录制、停止 |
| `CAM-too-small` | 选区过小无法容纳最小档+margin | 画中画隐藏；设置面板提示「选区过小，无法显示摄像头画面」 | 放大选区、关闭摄像头 |

横幅均为一次性 live region 公告，不重复播放（`shotx-ux-ui-spec.md` §14.2）；与麦克风状态矩阵（§10.1）同模板。

## 5. 键盘操作与焦点

| 控件 | 操作 |
| --- | --- |
| 摄像头开关（`O-RSET`） | `Tab` 到达，`Space` 切换开/关；在 `Tab` 循环内位于麦克风与鼠标设置之间（沿用现状按钮顺序） |
| 摄像头设置浮层 | 打开后焦点移入浮层：尺寸分段控件（左右方向键切换小/大）、开关行（`Tab` 遍历、`Space` 切换）；`Esc` 先关浮层（焦点回摄像头图标），再按 `O-RSET` 现有 `Esc` 链（返回选区） |
| 画中画窗口 | 不参与焦点循环（`ignoresMouseEvents`），无键盘操作 |

## 7. reduced-motion / 对比度

- 系统「减少动态效果」开启时：画中画出现/消失不做缩放/淡入淡出动画；切换尺寸直接切换，无过渡动画；loading spinner 可保留（因果反馈，120 ms 状态切换原则）。
- 系统「增强对比度」开启时：loading 提示文字、横幅与设置浮层遵循既有对比度规则（普通文字 ≥ 4.5:1，`shotx-ux-ui-spec.md` §14.3）；画中画圆角边界在浅色画面上保持可见（可加 1 pt 边框，待确认）。
- 画中画不闪烁、不用动画作为唯一状态提示。

## 9. 开发不可自行猜测清单（必办）

1. 权限弹窗置顶：任何系统权限请求发起时不得存在 `.screenSaver` 级蒙层（§1.3）——这是本变更单的验收关键。
2. 画中画位置：左下角 + margin，正方形 + 12 pt 圆角，替换现状右下角 4:3（§2.2）。
3. 两档尺寸像素值：96/192 pt；成片像素 = pt × backingScaleFactor（§2.3）。
4. 夹紧规则：不超出选区；过小隐藏 + 提示（§2.3）。
5. 预览与成片必须调用同一布局函数，坐标系不同、缩放因子不同（§2.4）。
6. 美颜不得假实现；模糊背景/美颜按系统能力隐藏或禁用并说明（§3.1）。
7. 摄像头权限仅在用户开启开关时请求；首次录屏默认关闭（§1.4）。
