# ShotX BRA-113 录屏 UI 标注（录制按钮两态/禁用态、首次默认关闭、O-RSET/O-REC 差异）

版本：v1.0（对应 `docs/shotx-prd-BRA113.md` BRA113-U 与用户补充评论，优先于既有规范冲突表述，冲突点名见 §9）
平台：macOS 14+，菜单栏应用
需求来源：BRA-113（父工单）；设计任务：本工单（BRA-114）
交付对象：macOS 客户端（Stage 2 BRA-116 实现）、QA（BRA-117）
范围：只做设计标注，不改业务代码

## 0. 依据与核对方式（必读）

本标注依据 `docs/shotx-prd-BRA113.md`（BRA113-U）、既有设计系统 `docs/shotx-ux-ui-spec.md`（§10.1 `O-RSET`、§10.2、§10.4 `O-REC`）、`docs/shotx-ux-ui-spec-BRA102.md`、`docs/shotx-ux-ui-spec-BRA71.md`（§6/§7，紧凑面板基线）、`docs/shotx-ux-ui-spec-BRA107.md`（字体，仅排除确认）及**现有 Figma 导出 SVG 资产** `Sources/ShotX/Assets/Figma/record-*.svg` 与**当前实现** `Sources/ShotX/RecordingCoordinator.swift`（`RecordingSetupView` / `RecordingSetupWindowController` / `RecordingStatusWindowController`）、`Sources/ShotX/AppModel.swift` 逐项核对生成。

**设计文件核对结论**：本次用户「更新并补充的录屏 UI 设计」未随工单提供新位图/新 SVG；仓库内现有的 `record-*.svg`（含 `record-menu.svg` 组合画板）即用户设计文件的 Figma 导出，是按钮两态的唯一权威视觉源。用户补充评论所指「录制按钮禁用状态」画板对应 `record-*-off.svg`（组内 id 为「录制按钮禁用状态」），「录屏-录制前」画板对应 `record-*-on.svg`。凡超出这些资产的视觉数值，沿用 BRA-102 的核对方式约定：以本文件为基线、标「待确认」，不阻断功能推进。

**核心结论（一句话）**：设计中的「关闭」与「禁用」是同一视觉——灰色图标 + 2 pt 红色斜线（`record-*-off.svg`，即「录制按钮禁用状态」画板）；按钮两态 = 正常图标（开）/ 斜线图标（关），且显示状态必须与功能实际可用状态一致。

## 1. 录制按钮两态总则（BRA113-U1/U2，设计为准）

`O-RSET` 紧凑面板内的四个录制源按钮全部使用 Figma 导出资产实现两种状态，**不新增第三方图标**。

### 1.1 资产清单与状态映射（开发不可自行猜测）

| 按钮 | 底部标签 | 开（on）资产 | 关（off）资产 | 状态单一真值 |
| --- | --- | --- | --- | --- |
| 扬声器 | 扬声器 | `record-speaker-on.svg` | `record-speaker-off.svg` | `AppSettings.systemAudio` |
| 麦克风 | 麦克风 | `record-microphone-on.svg` | `record-microphone-off.svg` | `AppSettings.microphone` |
| 摄像头 | 摄像头 | `record-camera-on.svg` | `record-camera-off.svg` | `AppSettings.cameraEnabled` |
| 鼠标设置 | 鼠标设置 | `record-cursor-on.svg` | `record-cursor-off.svg` | `showsCursor == true 或 showsClicks == true` |

- 四枚按钮尺寸均为 **40 × 36 pt**（资产 viewBox 0 0 40 36，按原样缩放渲染），行内间距 **16 pt**，整行宽 208 pt。
- **on 视觉**：图标路径填充 `#D9D9D9`，无斜线（资产组名「录屏-录制前」）。
- **off 视觉**：同一灰色图标 + **2 pt 对角斜线 `#FA5151`**，画板坐标为 `M28 19 L12 3`（即 40×36 画板内从右中向左上的 35° 斜线），四个 off 资产斜线完全一致（资产组名「录制按钮禁用状态」）。
- 每枚资产自带底部小字标签（扬声器/麦克风/摄像头/鼠标设置，`#D9D9D9`），属于按钮整体视觉的一部分，渲染时必须随资产一并显示，不得裁掉或另起文字。

### 1.2 两态切换语义（「正确指示功能开关状态」的验收核心）

按钮显示的视觉状态**必须等于该来源在录制中的实际启用状态**，而不是只反映开关布尔值：

| 来源 | 显示「开」的充分必要条件 |
| --- | --- |
| 扬声器 | `systemAudio == true` 且音频输出设备可用（屏幕录制权限已授予才能进入 `O-RSET`，视为前置满足） |
| 麦克风 | `microphone == true` 且 麦克风权限已授予 且 存在麦克风设备 |
| 摄像头 | `cameraEnabled == true` 且 摄像头权限已授予 且 存在摄像头设备（开启后出现画中画，BRA-102 §2.1） |
| 鼠标设置 | `showsCursor == true` 或 `showsClicks == true`（鼠标不涉及权限/设备） |

**切换规则**：

1. 用户点击按钮切换开关 → 立即请求对应权限（扬声器除外，见 §3.1）→ 成功后按钮呈 on 视觉；失败（权限拒绝/无设备/启动失败）→ **按钮自动回退 off 视觉**并给出提示（§4），绝不出现「显示开但实际未采集」的中间态。
2. 视觉状态由**单一数据源**驱动（上表真值列），开关数据、权限状态、设备状态三者共同解析，禁止用本地 UI 变量缓存状态导致与真实采集状态漂移。
3. 任何一次状态解析（进入设置态、权限回调、设备插拔、开关变更）后立即刷新四枚按钮视觉。

## 2. 禁用态（权限不可用/无设备）呈现与提示（BRA113-U2/A4）

设计只提供「开/关」两态资产，**无第三态视觉**。因此「禁用态」的表达口径为：**任何导致该来源无法采集的原因，一律呈现 off 视觉（红斜线）+ 横幅提示**；按钮始终可点击（点击即重试/重新申请），不出现无反馈置灰按钮。

| 状态 ID | 触发 | 按钮视觉 | 用户提示（横幅，一次 live region 公告，不重复） |
| --- | --- | --- | --- |
| `SRC-off` | 用户关闭 | off 资产 | 无 |
| `SRC-on` | 权限已授予 + 设备存在 + 开关开 | on 资产 | 无 |
| `SRC-no-permission` | 开启时权限拒绝/受限 | 回退 off 资产 | 「麦克风不可用。你仍可继续无麦克风录制。」/「摄像头不可用。你仍可继续无摄像头录制。」+ 动作「打开系统设置」（扬声器沿用 §10.1 系统声音模板） |
| `SRC-no-device` | 开启时无设备 | 回退 off 资产 | 「未找到麦克风」/「未找到音频输出设备」/「未找到摄像头」（沿用 §10.1 / BRA-102 §4） |
| `SRC-lost` | 录制中设备断开 | `O-REC` 内对应来源图标呈斜线 | 「麦克风已断开，其他来源仍在录制。」/「摄像头已断开，其他来源仍在录制。」（§10.4 / BRA-102 §4） |
| `SRC-pending` | 权限请求进行中 | 保持当前状态，该行显示小型 spinner | — |

- 拒绝/无设备只关闭本次无效来源，**不覆盖用户原先的设备/开关偏好**，设备恢复后仍需用户主动开启（§10.1 持久化口径）。
- 横幅的「打开系统设置」动作与 `O-REC` 的「停止」动作必须可用（见 §7 差异：现状为模态 alert，仅「好」，未达横幅+动作口径）。

## 3. 首次录屏默认关闭（BRA113-U3）

### 3.1 首次进入 `O-RSET` 的默认状态（全新安装，无持久化配置）

| 按钮 | 默认 | 依据 |
| --- | --- | --- |
| 扬声器 | **开** | `AppSettings.systemAudio` 默认 `true`（设计如此；系统声音不设独立 TCC 权限，macOS 14+ 屏幕录制权限已覆盖） |
| 麦克风 | **关（红斜线）** | `AppSettings.microphone` 默认 `false`（BRA-102 §1.4 已核实） |
| 摄像头 | **关（红斜线）** | `AppSettings.cameraEnabled` 默认 `false`（BRA-102 §1.4 已核实） |
| 鼠标设置 | **开** | `showsCursor`/`showsClicks` 默认 `true` |

### 3.2 规则（开发不可自行猜测）

1. 全新安装首次进入 `O-RSET`：麦克风、摄像头按钮显示 **off（红斜线）**；**不自动发起麦克风/摄像头权限请求**；仅当用户主动开启对应开关时才请求（沿用 `FR-BASE-04` / BRA-102 §1.4 按需申请口径）。
2. 「首次」的判定 = 无持久化 `AppSettings` 配置的全新安装；用户更改后设置持久化，后续沿用（§10.1），不属于「首次」。
3. `W-SET/录屏` 分区与 `O-RSET` 使用同一数据源（`AppSettings`），两侧状态与默认值必须一致。
4. 验收要点：清除 `AppSettings` 持久化后首次录屏，麦克风/摄像头按钮必须为红斜线 off 视觉；成片不含麦克风音轨与摄像头画中画；`W-SET` 内「麦克风」「摄像头画面」开关同为关。

## 4. 单按钮标注

### 4.1 扬声器

- 控件：按钮（点击即切换，无展开菜单；现状 `recordToggle("record-speaker", …)`）。
- 状态：`systemAudio`，默认开。开关切换即持久化。
- 权限：macOS 14+ 系统声音捕获依赖屏幕录制权限，进入 `O-RSET` 前已授予，**不再单独弹权限**（§10.1「首次打开系统声音触发权限请求」在本平台实际不适用，见 §9 C3）。
- 无输出设备：自动回退 off + 「未找到音频输出设备」；其余来源与开始录制仍可用。**现状缺口**：当前实现未在面板内检测音频输出设备存在性，见 §7。

### 4.2 麦克风

- 控件：按钮（点击即切换，无展开菜单；现状 `recordToggle("record-microphone", isOn: binding(\.microphone, permission: .microphone))`）。
- 状态：`microphone`，默认关。开启时请求麦克风权限；拒绝/无设备 → 自动回退 off + 提示（§4）。
- 设备选择入口：紧凑面板按钮本身不展开设备列表（沿用 BRA-71 §7.2「展开为就地浮层」或 `W-SET/录屏` 内选择，见 §9 待确认 6）；当前实现面板内无设备菜单，设备选择在 `W-SET` 分区，状态同步一致即可。

### 4.3 摄像头

- 控件：按钮（**点击展开设置浮层**，浮层内含「启用摄像头」开关 + 尺寸 小/大 + 镜像 + 模糊背景（系统支持时）；现状 `cameraMenu` Menu，BRA-102 §3.2 已落地）。
- 状态：`cameraEnabled`，默认关。开启即按需申请权限并启动画中画预览（BRA-102 §2.1），无需等录制开始。
- 按钮图标视觉仍按两态：`cameraEnabled` 为真显示 on 资产，否则 off 资产（红斜线）；浮层内开关与按钮图标必须同步。
- 选区过小无法容纳画中画：按钮视觉维持开启态，面板内显示「选区过小，无法显示摄像头画面」（BRA-102 §2.3 `CAM-too-small`），**按钮不因此回退 off**。

### 4.4 鼠标设置

- 控件：按钮（**点击展开浮层**，含「显示鼠标指针」「显示点击反馈」两个复选项；现状 `mouseMenu` Menu）。
- 状态：`showsCursor || showsClicks`。两者均关 → off 资产（红斜线）；任一开 → on 资产。
- 无权限/设备维度；点击反馈环为直径 24 pt、300 ms 圆环（§10.1），与本两态无关。

## 5. 键盘操作、焦点与 VoiceOver

### 5.1 键盘与焦点

| 控件 | 操作 |
| --- | --- |
| 扬声器/麦克风 | `Tab` 到达，`Space`/`Return` 切换开/关 |
| 摄像头/鼠标设置 | `Tab` 到达，`Space`/`Return`/方向键展开浮层；浮层内 `Tab` 遍历、`Space` 切换；`Esc` 先关浮层，再走面板 `Esc` 链（返回选区） |
| 开始录制 | `Return` 触发；面板内唯一 `defaultAction` |
| 焦点顺序 | 视觉顺序：开始录制 → 扬声器 → 麦克风 → 摄像头 → 鼠标设置 →（选区 → 8 把手 → 回面板）；**初始焦点 = 扬声器**（§10.1 口径；现状开始按钮在视觉首位，需显式设初始焦点为扬声器） |

### 5.2 VoiceOver

| 元素 | 标签 / Value |
| --- | --- |
| 扬声器 | 标签「扬声器」；value「已开启/已关闭」（对齐 BRA-71 §7.5「扬声器，已开启，开关」） |
| 麦克风 | 标签「麦克风」；value「已开启/已关闭」；开启时追加设备名（对齐 §14.2「麦克风，已开启，MacBook 麦克风」口径） |
| 摄像头 | 标签「摄像头」；value「已开启/已关闭」（BRA-102 §6，现状已有） |
| 鼠标设置 | 标签「鼠标设置」；value「已开启/已关闭」（开 = 显示指针或点击反馈任一启用） |
| 开始录制 | 标签「开始录制，按钮」 |

**现状缺口**：扬声器/麦克风/鼠标设置三枚按钮无 `accessibilityLabel`（仅摄像头 Menu 有），BRA-116 需补齐。

### 5.3 对比度与 reduced-motion

- 图标 `#D9D9D9` vs 面板 `#333333` ≈ 8.8:1（达标，非文字图形 ≥ 3:1）。
- 红斜线 `#FA5151` vs 图标灰 `#D9D9D9` ≈ 2.0:1（低于 3:1 图形对比度）；但状态识别**不只靠颜色**（有斜线/无斜线形状差），且斜线跨入 `#333333` 面板部分 ≈ 4.2:1。**结论**：保留设计资产原样；不得用颜色作为唯一状态提示（现有形状差已满足），`增强对比度` 模式不额外处理（待确认是否需要斜线描边增强）。
- 开始按钮绿底 `#07C160` + 白字 ≈ 2.6:1（低于正文 4.5:1）。此为设计资产；标注建议：保留资产，若 QA/用户反馈可读性差，可在按钮文字上加深色描边或调色（待确认，不阻塞）。
- reduced-motion：按钮两态切换为即时替换资产，无缩放/淡入淡出动画；摄像头 hint 出现/消失不带动画（现状符合）。

## 8. 提示形态差异（横幅 vs 模态 alert）

- 规范口径（§10.1/§10.4/BRA-102 §4）：错误与断开提示为**横幅**，一次性 live region 公告，可带动作（「打开系统设置」「停止」），不逐秒重复。
- 现状实现：`AppModel.showError` → SwiftUI `.alert`（`ShotXApp.swift:67-69`），仅「好」按钮，无动作按钮，非 live region。
- 结论：功能提示已触发、文案与规范一致；**形态与动作按钮**与规范不符（无「打开系统设置」「停止」动作）。BRA-116 按规范改为横幅形态（或由产品决策统一提示形态，见 §9 待确认 5）。本变更单验收以「提示出现、文案正确、不阻断继续录制」为准，横幅形态为待确认项。
